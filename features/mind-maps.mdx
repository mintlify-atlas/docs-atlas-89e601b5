Flowy transforms any GitHub repository into a fully navigable mind map the moment you paste its URL. Instead of opening dozens of files to understand how a codebase is structured, you get a visual hierarchy that exposes folder organization, file relationships, and import chains at a glance. Whether you're onboarding to a new project, auditing a legacy service, or preparing for a refactor, mind maps give you the spatial context that reading raw code never can.

## How mind maps are generated

When you submit a GitHub URL, Flowy follows a four-step pipeline to produce your map:

1. **URL ingestion** — Flowy parses the URL to extract the owner, repository name, and optional branch reference.
2. **API fetch** — The GitHub API is queried to retrieve the full recursive file tree.
3. **Parse & analyze** — The file tree is analyzed for folder hierarchy, file types, and import/dependency relationships. TypeScript projects are also checked for `tsconfig.json` to resolve path aliases before rendering.
4. **Render** — The processed graph is rendered on the interactive canvas as a node-based mind map.

For a deeper technical walkthrough of every step in this pipeline, see [How It Works](/how-it-works).

## Reading your mind map

Every node in your mind map represents a single file or directory in the repository:

- **Directory nodes** are rendered as larger, labeled branch points. They can be expanded or collapsed to reveal or hide their children, keeping the canvas uncluttered when you're focused on a particular area.
- **File nodes** are leaf-level nodes attached to their parent directory. Their label shows the filename and extension, giving you an immediate sense of the technology spread across the project.
- **Relationship edges** connect nodes that share an import or dependency link. An edge from file A to file B means A imports something from B. Edge direction is meaningful — follow the arrows to trace data flow through the codebase.

<Tip>
  If you're new to Flowy, start by pasting the URL of a well-known open-source repository — something like a popular React starter or a small Node.js utility library. Familiar code lets you validate that the map matches what you already know, making it much easier to learn the interface before mapping your own projects.
</Tip>

## Supported repository types

| Repository type | Requirements |
|---|---|
| Public repositories | No authentication needed — paste the URL and go |
| Private repositories | GitHub OAuth connection required |
| Monorepos | Fully supported; each package directory becomes a primary branch |
| TypeScript projects with `@/` aliases | Automatically resolved via `tsconfig.json` parsing |

<Info>
  Private repository access requires connecting your GitHub account via OAuth. This grants Flowy read-only access to the repositories you authorize. See [GitHub Integration](/reference/github-integration) for the full setup guide.
</Info>
