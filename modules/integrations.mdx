The Pro Integrations module extends Flowy beyond public repositories and manual refreshes. With this module you can authenticate against GitHub to map private and enterprise codebases without leaving the browser, configure webhooks so that maps regenerate themselves on every merge, step back in time to compare architectural complexity between commits, and ensure that TypeScript path aliases are resolved correctly so the dependency graph is always accurate.

## GitHub OAuth and Private Repositories

Connecting your GitHub account unlocks every private repository you have access to — personal repos, organisation repos, and enterprise installations — without requiring you to paste a personal access token or leave the browser.

Flowy requests only the scopes needed to read file trees and commit histories. The connection can be revoked at any time, immediately removing Flowy's ability to access any repository that was only reachable via the OAuth token.

For a full walkthrough of the OAuth flow and troubleshooting steps, see the [GitHub Integration reference](/reference/github-integration).

## Time Machine

Time Machine lets you answer the question: *has this codebase become more or less tangled over time?* Rather than reading changelogs or grepping through git blame, you select a specific point in history and let Flowy render what the architecture looked like then.

Choose an old commit or pull request and Flowy produces a visual representation of the map at that point, letting you compare it directly against the current state. This makes it straightforward to see whether complexity has increased, which modules have grown, and where new coupling has been introduced since that reference point.

<Note>
  Time Machine is available for both public and OAuth-connected private repositories. For very large repositories, historical fetches may take longer than a standard scan because Flowy must re-analyse the file tree from the selected commit.
</Note>

## Alias Support

Many modern JavaScript and TypeScript frameworks encourage path aliases to avoid deeply nested relative imports. Next.js, Vite, and Nuxt projects commonly configure an `@/` alias that maps to the `src/` directory. Without alias resolution, Flowy would render these imports as broken edges pointing to nowhere.

Flowy automatically reads your project's `tsconfig.json` to resolve these aliases before building the dependency graph. This means an import written as `@/components/ui/Button` correctly draws an edge to the right module on the canvas — the same way a TypeScript compiler would resolve it.

For a complete reference on supported alias patterns and edge cases, see the [tsconfig Alias Support reference](/reference/tsconfig-alias-support).

## Auto-Push Webhooks

Auto-Push Webhooks close the loop between your Git workflow and your Flowy maps. Once configured, every merge to your target branch triggers Flowy to re-scan the repository and regenerate the map — no manual intervention needed.

This is the mechanism that keeps the Git Sync indicator in the [Management dashboard](/modules/management) perpetually current for active projects. It also means that shareable map URLs (see [Social Features](/modules/social)) always reflect the current state of the codebase for anyone viewing them.

For setup instructions and configuration details, see the [Webhooks reference](/reference/webhooks).
