Software architecture is a team conversation, not a solo document. Flowy's Social Features are built around that idea — giving you the tools to share a live, explorable view of your repository with any teammate, annotate specific nodes with context that would otherwise live only in someone's head, and ensure that every shared link always reflects the latest state of the codebase. Whether you are onboarding a new hire, running a remote code review, or documenting a known area of technical debt, these features turn a private map into a shared resource.

## Sharing a map

Any map in your workspace can be published as a read-only public link. Once enabled, anyone with the URL can explore the full interactive canvas — panning, zooming, and reading node metadata — without needing a Flowy account.

This makes it straightforward to include a live architecture map in a pull request description, a Notion page, a Slack message, or any other channel your team uses. The recipient sees the same interactive view you do, just without editing access.

<Note>
  Shareable map URLs expose the full file structure and import graph of the repository to anyone who holds the link. For proprietary or commercially sensitive codebases, treat the link as you would any internal document and share it over secure channels.
</Note>

## Sticky Notes

Sticky Notes let you annotate the living map with institutional knowledge that never makes it into source code comments or commit messages. Pin a virtual note directly onto any node — marking technical debt, leaving onboarding hints for new developers, or flagging a module for discussion in an upcoming code review.

Notes stay attached to their node, so they surface naturally whenever anyone navigates to that part of the map. This keeps important context visible without requiring a separate issue tracker lookup or a separate documentation page.

## Keeping shared maps current

A shared map URL points to a living snapshot — it reflects the map as it was at the time of the last sync. If your team merges frequently, you will want shared maps to update automatically rather than going stale.

Configure Auto-Push Webhooks in the [Pro Integrations module](/modules/integrations) to trigger a map regeneration with each merge to master. Once a webhook is active, any teammate viewing the shared URL will always see a map that matches the latest commit — no re-sharing required, and no risk of someone making architectural decisions based on an outdated graph.
